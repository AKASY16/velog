<h4 id="물리적-설계-시에는-트랜잭션-처리량-응답-시간-디스크-용량-저장-공간의-효율화-등을-고려해야-한다">물리적 설계 시에는 트랜잭션 처리량, 응답 시간, 디스크 용량, 저장 공간의 효율화 등을 고려해야 한다.</h4>

<h3 id="1-관계의-형태">1. 관계의 형태</h3>
<h4 id="일대일11-개체-집합-a의-각-원소가-개체-집합-b의-각-원소와-11로-대응하는-관계">일대일(1:1): 개체 집합 A의 각 원소가 개체 집합 B의 각 원소와 1:1로 대응하는 관계</h4>
<h4 id="일대다1n-개체-집합-a의-각-원소는-개체-집합-b의-각-원소-여러-개와-대응하지만-b의-각-원소는-a의-원소-단-한개와-대응하고-있는-관계">일대다(1:N): 개체 집합 A의 각 원소는 개체 집합 B의 각 원소 여러 개와 대응하지만, B의 각 원소는 A의 원소 단 한개와 대응하고 있는 관계</h4>
<h4 id="다대다nm-개체-집합-a의-각-원소가-개체-집합-b의-각-원소-여러개와-대응하고-반대의-경우도-동일">다대다(N:M): 개체 집합 A의 각 원소가 개체 집합 B의 각 원소 여러개와 대응하고, 반대의 경우도 동일.</h4>
<br />

<h3 id="2-데이터-모델에-표시할-요소">2. 데이터 모델에 표시할 요소</h3>

<h4 id="연산operator-데이터베이스에-저장된-데이터를-처리하는-작업에-대한-명세-데이터베이스를-조작하는-기본적인-도구">연산(Operator): 데이터베이스에 저장된 데이터를 처리하는 작업에 대한 명세. 데이터베이스를 조작하는 기본적인 도구.</h4>
<h4 id="제약-조건constraint-데이터베이스에-저장될-수-있는-실제-데이터의-논리적-제약-조건">제약 조건(Constraint): 데이터베이스에 저장될 수 있는 실제 데이터의 논리적 제약 조건.</h4>

<h3 id="1-개체-무결성entity-integrity-실체-무결성">1. 개체 무결성(Entity Integrity, 실체 무결성)</h3>

<h1 id="관계대수-및-관계해석">관계대수 및 관계해석</h1>
<br />

<h3 id="1-관계대수의-개요">1. 관계대수의 개요</h3>
<h4 id="관계형-데이터베이스에서-원하는-정보를-어떻게-유도하는가를-기술하는-절차적-언어를-말한다">관계형 데이터베이스에서 원하는 정보를 어떻게 유도하는가를 기술하는 절차적 언어를 말한다.</h4>
<h4 id="릴레이션을-처리하기-위해-연산자와-연산-규칙을-제공하는-언어이며-피연산자-결과-모두-릴레이션이다">릴레이션을 처리하기 위해, 연산자와 연산 규칙을 제공하는 언어이며 피연산자, 결과 모두 릴레이션이다.</h4>
<br />

<h3 id="2-순수-관계-연산자">2. 순수 관계 연산자</h3>
<h4 id="select-project-join-division이-있다">Select, Project, Join, Division이 있다.</h4>
<h4 id="select의-경우-기호는-σ이며-표기-형식은-sigma_조건r이다-조건을-만족하는-튜플의-부분집합을-구해-새-릴레이션을-만드는-연산이다">Select의 경우 기호는 $σ$이며 표기 형식은 $\sigma_{&lt;조건&gt;}(R)$이다. 조건을 만족하는 튜플의 부분집합을 구해 새 릴레이션을 만드는 연산이다.</h4>
<h4 id="project의-경우-기호는-pi이며-표기-형식은-pi_속성리스트r이다-속성리스트에-제시된-속성-값만을-추출해-새-릴레이션을-만드는-연산이다">Project의 경우 기호는 $\pi$이며 표기 형식은 $\pi_{&lt;속성리스트&gt;}(R)$이다. 속성리스트에 제시된 속성 값만을 추출해 새 릴레이션을 만드는 연산이다.</h4>
<h4 id="join의-경우-기호는-bowtie이며-표기-형식은-r-bowtie_조건-s이다-공통-속성을-중심으로-두-개의-릴레이션을-합쳐-하나의-릴레이션으로-만드는-연산이다">Join의 경우 기호는 $\bowtie$이며 표기 형식은 $R \bowtie_{&lt;조건&gt;} S$이다. 공통 속성을 중심으로 두 개의 릴레이션을 합쳐 하나의 릴레이션으로 만드는 연산이다.</h4>
<h4 id="division의-경우-기호는-div이며-표기-형식은-r-div-s이다">Division의 경우 기호는 $\div$이며 표기 형식은 $R \div S$이다.</h4>
<br />

<h3 id="3-일반-집합-연산자">3. 일반 집합 연산자</h3>
<h4 id="일반적으로-카디널리티는-튜플행의-갯수를-의미하고-디그리차수는-속성열의-갯수를-의미한다">일반적으로 카디널리티는 튜플(행)의 갯수를 의미하고 디그리(차수)는 속성(열)의 갯수를 의미한다.</h4>
<h4 id="일반-집합-연산자에는-합집합union-교집합intersection-차집합difference-교차곱cartesian-product가-있다">일반 집합 연산자에는 합집합(UNION), 교집합(INTERSECTION), 차집합(DIFFERENCE), 교차곱(CARTESIAN PRODUCT)가 있다.</h4>
<h4 id="합집합의-카디널리티는-두-릴레이션-카디널리티의-합보다-크지-않다">합집합의 카디널리티는 두 릴레이션 카디널리티의 합보다 크지 않다.</h4>
<h4 id="교집합의-카디널리티는-두-릴레이션-중-카디널리티가-적은-릴레이션의-카디널리티보다-크지-않다">교집합의 카디널리티는 두 릴레이션 중 카디널리티가 적은 릴레이션의 카디널리티보다 크지 않다.</h4>
<h4 id="차집합의-카디널리티는-릴레이션-r의-카디널리티보다-크지-않다">차집합의 카디널리티는 릴레이션 R의 카디널리티보다 크지 않다.</h4>
<h4 id="교차곱에서-디그리는-두-릴레이션의-디그리의-합이고-카디널리티는-두-릴레이션의-카디널리티의-곱이다">교차곱에서 디그리는 두 릴레이션의 디그리의 합이고, 카디널리티는 두 릴레이션의 카디널리티의 곱이다.</h4>
<br />

<h3 id="4-관계해석relational-calculus">4. 관계해석(Relational Calculus)</h3>
<h4 id="코드e-f-codd가-수학의-predicate-calculus술어-해석에-기반을-두고-관계-데이터베이스를-위해-제안한-것">코드(E. F. Codd)가 수학의 Predicate Calculus(술어 해석)에 기반을 두고 관계 데이터베이스를 위해 제안한 것.</h4>
<h4 id="관계해석은-원하는-정보가-무엇인지만-정의하는-비절차적-특성을-지닌다-기본적으로-관계해석과-관계대수는-관계-데이터베이스를-처리하는-기능과-능력-면에서는-동등하다-이처럼-관계대수와-동등한-능력을-갖춘-언어를-관계적으로-완전하다고-한다">관계해석은 원하는 정보가 무엇인지만 정의하는 비절차적 특성을 지닌다. 기본적으로 관계해석과 관계대수는 관계 데이터베이스를 처리하는 기능과 능력 면에서는 동등하다. 이처럼 관계대수와 동등한 능력을 갖춘 언어를 '관계적으로 완전하다'고 한다.</h4>
<h4 id="주요-논리-기호로는-forall와-exists가-있다">주요 논리 기호로는 $\forall$와 $\exists$가 있다.</h4>
<h4 id="forall는-전칭-정량자로-릴레이션의-모든-튜플-t가-조건을-만족함을-의미한다">$\forall$는 전칭 정량자로 릴레이션의 모든 튜플 $t$가 조건을 만족함을 의미한다.</h4>
<h4 id="exists는-존재-정량자로-릴레이션에-조건을-만족하는-튜플-t가-최소한-하나-존재함을-의미한다">$\exists$는 존재 정량자로, 릴레이션에 조건을 만족하는 튜플 $t$가 최소한 하나 존재함을 의미한다.</h4>
<br />

<h1 id="정규화nomalization">정규화(Nomalization)</h1>
<br />

<h3 id="1-정규화의-개요">1. 정규화의 개요</h3>
<h4 id="종속성-이론을-이용해-잘못-설계된-관계형-스키마를-더-작은-속성의-세트로-쪼개-바람직한-스키마로-만드는-과정이다">종속성 이론을 이용해 잘못 설계된 관계형 스키마를 더 작은 속성의 세트로 쪼개 바람직한 스키마로 만드는 과정이다.</h4>
<h4 id="데이터베이스의-논리적-설계-단계에서-수행한다">데이터베이스의 논리적 설계 단계에서 수행한다.</h4>
<br />

<h3 id="2-정규화의-목적">2. 정규화의 목적</h3>
<h4 id="어떤-릴레이션이든-데이터베이스-내에서-표현-가능하도록-만든다">어떤 릴레이션이든 데이터베이스 내에서 표현 가능하도록 만든다.</h4>
<h4 id="효과적인-검색-알고리즘을-생성할-수-있다">효과적인 검색 알고리즘을 생성할 수 있다.</h4>
<h4 id="데이터-중복을-배제하여-이상의-발생-방지-및-자료-저장-공간-최소화가-가능해진다">데이터 중복을 배제하여 이상의 발생 방지 및 자료 저장 공간 최소화가 가능해진다.</h4>
<h4 id="데이터-삽입-시-릴레이션-재구성의-필요성을-줄인다">데이터 삽입 시 릴레이션 재구성의 필요성을 줄인다.</h4>
<br />

<h3 id="3-이상anomaly의-개념-및-종류">3. 이상(Anomaly)의 개념 및 종류</h3>
<h4 id="정규화를-거치지-않으면-데이터들이-불필요하게-중복되어-예기치-못하게-겪게-되는-곤란한-현상을-말한다">정규화를 거치지 않으면 데이터들이 불필요하게 중복되어 예기치 못하게 겪게 되는 곤란한 현상을 말한다.</h4>
<h4 id="삽입-이상insertion-anomaly-릴레이션에-데이터를-삽입할-때-원하지-않은-값도-같이-삽입되는-현상">삽입 이상(Insertion Anomaly): 릴레이션에 데이터를 삽입할 때, 원하지 않은 값도 같이 삽입되는 현상.</h4>
<h4 id="예시로-만약-사원번호-이름-부서명-프로젝트명이-한-테이블에-섞여-있다고-가정하자-신입-사원을-등록할-때-아직-참여한-프로젝트가-없다면-억지로-유령-프로젝트-데이터를-함께-입력해야만-하는-경우이다">예시로, 만약 [사원번호, 이름, 부서명, 프로젝트명]이 한 테이블에 섞여 있다고 가정하자. 신입 사원을 등록할 때, 아직 참여한 프로젝트가 없다면 억지로 유령 프로젝트 데이터를 함께 입력해야만 하는 경우이다.</h4>
<h4 id="삭제-이상deletion-anomaly-릴레이션에서-한-튜플을-삭제했을-때-의도치않게-상관없는-값들도-같이-삭제되는-연쇄가-일어나는-현상">삭제 이상(Deletion Anomaly): 릴레이션에서 한 튜플을 삭제했을 때, 의도치않게 상관없는 값들도 같이 삭제되는 연쇄가 일어나는 현상.</h4>
<h4 id="예시로-한-사원이-퇴사하여-그-정보를-삭제했더니-그-사원이-담당하던-유일한-부서나-프로젝트-정보-등-연결된-정보까지-릴레이션에서-완전히-사라지는-경우이다">예시로, 한 사원이 퇴사하여 그 정보를 삭제했더니, 그 사원이 담당하던 유일한 부서나 프로젝트 정보 등 연결된 정보까지 릴레이션에서 완전히 사라지는 경우이다.</h4>
<h4 id="갱신-이상update-anomaly-릴레이션에서-튜플에-있는-속성값을-갱신할-때-일부-튜플의-정보만-갱신되어-정보에-모순이-생기는-현상">갱신 이상(Update Anomaly): 릴레이션에서 튜플에 있는 속성값을 갱신할 때, 일부 튜플의 정보만 갱신되어 정보에 모순이 생기는 현상.</h4>
<h4 id="예시로-부서명이-변경되어-소속-사원들의-정보를-수정할-때-일부-사원만-수정되고-나머지는-옛-이름으로-남아-데이터-간에-불일치가-발생하는-경우이다">예시로, 부서명이 변경되어 소속 사원들의 정보를 수정할 때, 일부 사원만 수정되고 나머지는 옛 이름으로 남아 데이터 간에 불일치가 발생하는 경우이다.</h4>
<br />

<h3 id="4-정규화-과정">4. 정규화 과정</h3>
<h4 id="비정규-릴레이션---1nf---2nf---3nf---bcnf---4nf---5nf-의-과정으로-이루어진다">비정규 릴레이션 -&gt; 1NF -&gt; 2NF -&gt; 3NF -&gt; BCNF -&gt; 4NF -&gt; 5NF 의 과정으로 이루어진다.</h4>
<h4 id="비정규---1nf는-도메인이-원자값이-목적이다-모든-속성이-원자값더-이상-쪼갤-수-없는-값을-갖도록-분해하는-것이다">비정규 -&gt; 1NF는 도메인이 원자값이 목적이다. 모든 속성이 원자값(더 이상 쪼갤 수 없는 값)을 갖도록 분해하는 것이다.</h4>
<h4 id="1nf---2nf는-부분-함수적-종속-제거가-목적이다-기본키의-부분-집합에만-종속되는-속성들을-분해하여-모든-속성이-기본키에-완전-함수적-종속이-되도록-하는-것이다">1NF -&gt; 2NF는 부분 함수적 종속 제거가 목적이다. 기본키의 부분 집합에만 종속되는 속성들을 분해하여 모든 속성이 기본키에 완전 함수적 종속이 되도록 하는 것이다.</h4>
<h4 id="2nf---3nf는-이행적-함수적-종속-제거가-목적이다-기본키를-거쳐-다른-속성에-종속되는a-→-b-→-c-관계를-분해하여-직접-종속-관계만-남기는-것이다">2NF -&gt; 3NF는 이행적 함수적 종속 제거가 목적이다. 기본키를 거쳐 다른 속성에 종속되는(A → B → C) 관계를 분해하여 직접 종속 관계만 남기는 것이다.</h4>
<h4 id="3nf---bcnf는-결정자이면서-후보키가-아닌-것-제거가-목적이다-모든-결정자가-후보키가-되도록-릴레이션을-더-쪼개어-엄격한-제약-조건을-만드는-것이다">3NF -&gt; BCNF는 결정자이면서 후보키가 아닌 것 제거가 목적이다. 모든 결정자가 후보키가 되도록 릴레이션을 더 쪼개어 엄격한 제약 조건을 만드는 것이다.</h4>
<h4 id="bcnf---4nf는-다치-종속multi-valued-dependency-제거가-목적이다-하나의-릴레이션에-두-개-이상의-독립적인-다치-종속이-존재하지-않게-분해하는-것이다">BCNF -&gt; 4NF는 다치 종속(Multi-valued Dependency) 제거가 목적이다. 하나의 릴레이션에 두 개 이상의 독립적인 다치 종속이 존재하지 않게 분해하는 것이다.</h4>
<h4 id="4nf---5nf는-조인-종속성-이용join-dependency이--목적이다-릴레이션이-분해되었다가-다시-조인되었을-때-손실이-없도록-모든-조인-종속이-후보키를-통해서만-성립되게-분해하는-것이다">4NF -&gt; 5NF는 조인 종속성 이용(Join Dependency)이  목적이다. 릴레이션이 분해되었다가 다시 조인되었을 때 손실이 없도록, 모든 조인 종속이 후보키를 통해서만 성립되게 분해하는 것이다.</h4>
