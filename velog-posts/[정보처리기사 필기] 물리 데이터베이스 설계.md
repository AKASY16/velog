<h1 id="트랙잭션-분석--crud-분석">트랙잭션 분석 / CRUD 분석</h1>
<br />

<h3 id="1-트랜잭션transaction-정의">1. 트랜잭션(Transaction) 정의</h3>
<h4 id="db의-상태를-변환시키는-논리적-기능을-수행하기-위한-작업의-단위-혹은-한꺼번에-수행되어야-할-일련의-연산을-의미한다">DB의 상태를 변환시키는 논리적 기능을 수행하기 위한 작업의 단위 혹은 한꺼번에 수행되어야 할 일련의 연산을 의미한다.</h4>
<h4 id="예를-들어-쇼핑몰에서-상품을-구매할-때-고객의-결제-처리와-상품의-재고-차감은-중간에-어느-하나만-실행되어서는-안-되며-반드시-모두-성공commit하거나-에러-발생-시-모두-취소rollback되어야-하는-하나의-트랜잭션-단위이다">예를 들어, 쇼핑몰에서 상품을 구매할 때 '고객의 결제 처리'와 '상품의 재고 차감'은 중간에 어느 하나만 실행되어서는 안 되며, 반드시 모두 성공(Commit)하거나 에러 발생 시 모두 취소(Rollback)되어야 하는 하나의 트랜잭션 단위이다.</h4>
<br />

<h3 id="2-트랜잭션의-상태">2. 트랜잭션의 상태</h3>
<h4 id="활동active-트랜잭션이-실행-중인-상태">활동(Active): 트랜잭션이 실행 중인 상태.</h4>
<h4 id="실패failed-트랜잭션-실행에-오류가-발생해-중단된-상태">실패(Failed): 트랜잭션 실행에 오류가 발생해 중단된 상태.</h4>
<h4 id="철회aborted-트랜잭션이-비정상적으로-종료되어-rollback-연산을-수행한-상태">철회(Aborted): 트랜잭션이 비정상적으로 종료되어 Rollback 연산을 수행한 상태.</h4>
<h4 id="부분-완료partially-commited-트랜잭션을-모두-성공적으로-수행한-후-commit-연산이-실행되기-직전인-상태">부분 완료(Partially Commited): 트랜잭션을 모두 성공적으로 수행한 후, Commit 연산이 실행되기 직전인 상태</h4>
<h4 id="완료committed-트랜잭션을-모두-성공적으로-실행한-후-commit-연산을-실행한-후의-상태">완료(Committed): 트랜잭션을 모두 성공적으로 실행한 후, Commit 연산을 실행한 후의 상태.</h4>
<br />

<h3 id="3-트랜잭션의-특성">3. 트랜잭션의 특성</h3>
<h4 id="atomicity원자성-트랜잭션의-연산은-모두-반영될-수-있도록-완료commit되든지-그게-아니라면-모두-반영되지-않도록-복구rollback되어야-함">Atomicity(원자성): 트랜잭션의 연산은 모두 반영될 수 있도록 완료(Commit)되든지, 그게 아니라면 모두 반영되지 않도록 복구(Rollback)되어야 함.</h4>
<h4 id="comsistency일관성-트랜잭션이-실행을-성공적으로-완료했다면-언제나-일관성있는-db-상태로-변환되어야-함">Comsistency(일관성): 트랜잭션이 실행을 성공적으로 완료했다면, 언제나 일관성있는 DB 상태로 변환되어야 함.</h4>
<h4 id="isolation독립성-둘-이상의-트랜잭션이-동시-실행되면-어느-하나가-실행되고-있다면-다른-트랜잭션은-연산에-끼어들-수-없음">Isolation(독립성): 둘 이상의 트랜잭션이 동시 실행되면 어느 하나가 실행되고 있다면 다른 트랜잭션은 연산에 끼어들 수 없음.</h4>
<h4 id="durability영속성-트랜잭션이-성공적으로-수행되었다면-시스템이-고장났더라도-트랜잭션의-결과가-영구적으로-반영되어야-함">Durability(영속성): 트랜잭션이 성공적으로 수행되었다면 시스템이 고장났더라도 트랜잭션의 결과가 영구적으로 반영되어야 함.</h4>

<h4 id="사용자에게-접근이-허용된-자료만-제한적으로-보여주기-위해-하나-이상의-기본-테이블에서-유도된-가상-테이블이다-이렇듯-접근-제어를-통해-보안을-제공한다">사용자에게 접근이 허용된 자료만 제한적으로 보여주기 위해 하나 이상의 기본 테이블에서 유도된 가상 테이블이다. 이렇듯 접근 제어를 통해 보안을 제공한다.</h4>
<h4 id="뷰가-정의된-기본-테이블이나-뷰가-삭제되면-삭제된-뷰나-테이블을-기초로-하는-뷰도-삭제된다">뷰가 정의된 기본 테이블이나 뷰가 삭제되면 삭제된 뷰나 테이블을 기초로 하는 뷰도 삭제된다.</h4>

<h1 id="파티션의-설계">파티션의 설계</h1>
<br />

<h3 id="1-파티션의-종류">1. 파티션의 종류</h3>
<h4 id="범위-분할range-partitioning-지정한-열의-값을-기준으로-범위를-지정하여-분할">범위 분할(Range Partitioning): 지정한 열의 값을 기준으로 범위를 지정하여 분할.</h4>
<h4 id="해시-분할hash-partitioning-해시-함수를-적용한-결과값에-따라-데이터를-분할한다-고객번호-주민번호처럼-데이터가-고른-컬럼에-효과적이다">해시 분할(Hash Partitioning): 해시 함수를 적용한 결과값에 따라 데이터를 분할한다. 고객번호, 주민번호처럼 데이터가 고른 컬럼에 효과적이다.</h4>
<h4 id="조합-분할composite-partitioning-우선-범위-분할로-분할한-후-해시-함수를-적용해-다시-분할한-방법이다-범위-분할을-했는데도-너무-커서-관리가-어려우면-사용한다">조합 분할(Composite Partitioning): 우선 범위 분할로 분할한 후, 해시 함수를 적용해 다시 분할한 방법이다. 범위 분할을 했는데도 너무 커서 관리가 어려우면 사용한다.</h4>
<h4 id="목록-분할list-partitioning-지정한-열-값에-대해-목록을-만들어서-분할한다">목록 분할(List Partitioning): 지정한 열 값에 대해 목록을 만들어서 분할한다.</h4>
<h4 id="라운드-로빈-분할round-robin-partitioning-레코드를-균일하게-분배하는-방식이며-레코드가-순차적으로-분배된다-기본키가-필요-없다">라운드 로빈 분할(Round Robin Partitioning): 레코드를 균일하게 분배하는 방식이며 레코드가 순차적으로 분배된다. 기본키가 필요 없다.</h4>
<br />

<h1 id="분산-데이터베이스-설계">분산 데이터베이스 설계</h1>
<br />

<h3 id="1-분산-데이터베이스의-구성-요소">1. 분산 데이터베이스의 구성 요소</h3>
<h4 id="분산-처리기-분산-데이터베이스-통신-네트워크">분산 처리기, 분산 데이터베이스, 통신 네트워크</h4>
<br />

<h3 id="2-분산-데이터베이스의-목표">2. 분산 데이터베이스의 목표</h3>
<h4 id="위치-투명성location-transparency-데이터베이스의-실제-위치는-알-필요-없이-데이터베이스의-논리적-명칭만으로-액세스-가능">위치 투명성(Location Transparency): 데이터베이스의 실제 위치는 알 필요 없이, 데이터베이스의 논리적 명칭만으로 액세스 가능.</h4>
<h4 id="중복-투명성replication-transparency-동일-데이터가-여러-데이터베이스에-중복되어있더라도-사용자는-하나의-데이터만-있는-것처럼-사용-가능하고-시스템은-자동으로-여러-자료에-대한-작업을-수행한다">중복 투명성(Replication Transparency): 동일 데이터가 여러 데이터베이스에 중복되어있더라도, 사용자는 하나의 데이터만 있는 것처럼 사용 가능하고, 시스템은 자동으로 여러 자료에 대한 작업을 수행한다.</h4>
<h4 id="병행-투명성concurrency-transparency-분산-데이터베이스에서-다수의-트랜잭션이-동시에-실행되더라도-결과는-영향을-받지-않는다">병행 투명성(Concurrency Transparency): 분산 데이터베이스에서 다수의 트랜잭션이 동시에 실행되더라도 결과는 영향을 받지 않는다.</h4>
<h4 id="장애-투명성failure-transparency-트랜잭션-dbms-네트워크-컴퓨터-등의-장애-사유에도-불구하고-트랜잭션을-정확하게-처리한다">장애 투명성(Failure Transparency): 트랜잭션, DBMS, 네트워크, 컴퓨터 등의 장애 사유에도 불구하고 트랜잭션을 정확하게 처리한다.</h4>
<br />

<h3 id="3-분산-데이터베이스의-장단점">3. 분산 데이터베이스의 장단점</h3>
<h4 id="시스템-성능이-향상되고-중앙-컴퓨터의-장애가-전체-시스템에-영향을-끼치지-않으며-점진적으로-시스템을-확장시킬-수-있는-장점이-있다">시스템 성능이 향상되고 중앙 컴퓨터의 장애가 전체 시스템에 영향을 끼치지 않으며, 점진적으로 시스템을 확장시킬 수 있는 장점이 있다.</h4>
<h4 id="dbms가-수행할-기능이-복잡하고-db설계가-어려우며-개발-비용이-증가한다는-단점이-있다">DBMS가 수행할 기능이 복잡하고, DB설계가 어려우며 개발 비용이 증가한다는 단점이 있다.</h4>
<br />

<h1 id="데이터베이스-보안---접근통제">데이터베이스 보안 - 접근통제</h1>
<br />

<h3 id="1-접근통제-기술">1. 접근통제 기술</h3>
<h4 id="임의-접근통제dac-discretionary-access-control-데이터에-접근하는-사용자의-신원에-따라-접근-권한을-부여">임의 접근통제(DAC; Discretionary Access Control): 데이터에 접근하는 사용자의 신원에 따라 접근 권한을 부여</h4>
<h4 id="강제-접근통제mac-mandatory-access-control-주체와-객제의-등급을-비교해-접근-권한을-부여함">강제 접근통제(MAC; Mandatory Access Control): 주체와 객제의 등급을 비교해 접근 권한을 부여함.</h4>

<h3 id="1-dasdirect-attached-storage">1. DAS(Direct Attached Storage)</h3>
<h4 id="서버-저장장치를-직접-연결하는-방식-구축-비용-및-유지보수-비용이-저렴하다">서버-저장장치를 직접 연결하는 방식. 구축 비용 및 유지보수 비용이 저렴하다.</h4>
<h4 id="확장성-및-유연성이-떨어지지만-데이터가-적고-공유가-필요-없는-환경에서-적합하다">확장성 및 유연성이 떨어지지만, 데이터가 적고 공유가 필요 없는 환경에서 적합하다.</h4>

<h3 id="2-sanstorage-area-network">2. SAN(Storage Area Network)</h3>
<h4 id="das의-빠름과-nas의-파일-공유를-혼합한-방식이다-서버-저장장치를-연결하는-전용-네트워크를-별도로-구성한다">DAS의 빠름과 NAS의 파일 공유를 혼합한 방식이다. 서버-저장장치를 연결하는 전용 네트워크를 별도로 구성한다.</h4>
<h4 id="광-채널-스위치를-이용해-전용-네트워크를-구성하며-광케이블로-연결되어있어-처리-속도가-빠르다">광 채널 스위치를 이용해 전용 네트워크를 구성하며 광케이블로 연결되어있어 처리 속도가 빠르다.</h4>
<h4 id="san에-사용되는-프로토콜로는-iscsi-fc-fcoe-등이-있다">SAN에 사용되는 프로토콜로는 iSCSI, FC, FCoE 등이 있다.</h4>
