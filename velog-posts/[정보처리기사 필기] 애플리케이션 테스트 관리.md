<h3 id="1-확인validation--검증verification">1. 확인(Validation) / 검증(Verification)</h3>
<h4 id="확인validation-사용자의-입장에서-개발한-소프트웨어가-요구사항에-맞게-개발되었는지-확인하는-작업">확인(Validation): '사용자의 입장'에서 개발한 소프트웨어가 요구사항에 맞게 개발되었는지 확인하는 작업.</h4>
<h4 id="검증verification-개발자의-입장에서-개발한-소프트웨어가-명세서에-맞게-개발되었는지-검증하는-작업">검증(Verification): '개발자의 입장'에서 개발한 소프트웨어가 명세서에 맞게 개발되었는지 검증하는 작업.</h4>
<br />

<h3 id="2-파레토-법칙pareto-principle">2. 파레토 법칙(Pareto Principle)</h3>
<h4 id="소프트웨어-테스트에서-오류의-80는-20의-모듈에서-발견된다는-법칙이다">소프트웨어 테스트에서 오류의 80%는 20%의 모듈에서 발견된다는 법칙이다.</h4>

<h3 id="3-결함-집중">3. 결함 집중</h3>
<h4 id="파레토-법칙이-좌우한다">파레토 법칙이 좌우한다.</h4>
<h4 id="결함이-발생한-모델은-계속-추가로-결함이-발생할-확률이-높으며-대부분의-결함은-소수-특정-모듈에-집중해서-발생된다는-것을-의미한다">결함이 발생한 모델은 계속 추가로 결함이 발생할 확률이 높으며, 대부분의 결함은 소수 특정 모듈에 집중해서 발생된다는 것을 의미한다.</h4>

<h3 id="1-화이트박스-테스트whitebox-test">1. 화이트박스 테스트(Whitebox Test)</h3>
<h4 id="모듈의-코드를-오픈시킨-상태에서-원시-코드의-모든-경로를-테스트해-테스트-케이스를-설계하는-방법-원시-코드의-모든-문장을-한-번-이상-실행함으로써-수행된다">모듈의 코드를 오픈시킨 상태에서 원시 코드의 모든 경로를 테스트해 테스트 케이스를 설계하는 방법. 원시 코드의 모든 문장을 한 번 이상 실행함으로써 수행된다.</h4>
<h4 id="프로그램-제어-구조에-따라-선택-반복-등의-분기점부분들을-수행함으로써-논리적-경로를-제어한다">프로그램 제어 구조에 따라 선택, 반복 등의 분기점부분들을 수행함으로써 논리적 경로를 제어한다.</h4>

<h4 id="제어-구조-검사control-structure-testing-조건-검사-루프-검사-데이터-흐름-검사">제어 구조 검사(Control Structure Testing): 조건 검사, 루프 검사, 데이터 흐름 검사</h4>
<br />

<h3 id="3-블랙박스-테스트로-발견-가능한-오류">3. 블랙박스 테스트로 발견 가능한 오류</h3>
<h4 id="비정상-자료를-입력해도-오류-처리를-수행하지-않거나-정상-자료를-입력해도-요구된-기능이-제대로-수행되지-않는-경우">비정상 자료를 입력해도 오류 처리를 수행하지 않거나, 정상 자료를 입력해도 요구된 기능이 제대로 수행되지 않는 경우.</h4>
<h4 id="경계값을-입력할-경우-요구된-출력-결과가-나오지-않는-경우">경계값을 입력할 경우, 요구된 출력 결과가 나오지 않는 경우.</h4>
<br />

<h3 id="4-블랙박스-테스트의-종류">4. 블랙박스 테스트의 종류</h3>
<h4 id="동치-분할-검사equivalence-partitioning-testing-프로그램-입력-조건에-맞는-자료의-수와-맞지-않는-자료의-수를-균등하게-하여-테스트-케이스를-정하고-맞는-결과가-출력되는지-확인하는-기법">동치 분할 검사(Equivalence Partitioning Testing): 프로그램 입력 조건에 맞는 자료의 수와 맞지 않는 자료의 수를 균등하게 하여 테스트 케이스를 정하고, 맞는 결과가 출력되는지 확인하는 기법.</h4>
<h4 id="경계값-분석boundary-value-analysis-입력-조건의-경계값을-테스트-케이스로-선정하여-검사하는-기법">경계값 분석(Boundary Value Analysis): 입력 조건의 경계값을 테스트 케이스로 선정하여 검사하는 기법.</h4>
<h4 id="원인-효과-그래프-검사cause-effect-graphing-testing-입력-데이터간의-관계-및-출력에-영향을-미치는-상황을-체계적으로-분석한-후-효용성이-높은-테스트-케이스를-선정하여-검사하는-기법">원인-효과 그래프 검사(Cause-Effect Graphing Testing): 입력 데이터간의 관계 및 출력에 영향을 미치는 상황을 체계적으로 분석한 후, 효용성이 높은 테스트 케이스를 선정하여 검사하는 기법.</h4>
<h4 id="오류-예측-검사error-gussing-숙련된-개발자가-과거의-경험이나-감각으로-테스트하는-기법">오류 예측 검사(Error Gussing): 숙련된 개발자가 과거의 경험이나 감각으로 테스트하는 기법.</h4>
<h4 id="비교-검사comparison-testing-여러-버전의-프로그램에-동일한-테스트-자료로-테스트하여-동일한-결과가-나오는지-테스트하는-기법">비교 검사(Comparison Testing): 여러 버전의 프로그램에 동일한 테스트 자료로 테스트하여 동일한 결과가 나오는지 테스트하는 기법.</h4>

<h3 id="3-테스트-오라클의-종류">3. 테스트 오라클의 종류</h3>
<h4 id="참true-오라클-모든-테스트-케이스의-입력-값에-대해-기대하는-결과를-제공하는-오라클-발생된-모든-오류를-검출할-수-있음">참(True) 오라클: 모든 테스트 케이스의 입력 값에 대해 기대하는 결과를 제공하는 오라클. 발생된 모든 오류를 검출할 수 있음.</h4>
<h4 id="샘플링sampling-오라클-특정한-몇몇-케이스의-입력값에-대해서만-기대하는-결과를-제공하는-오라클">샘플링(Sampling) 오라클: 특정한 몇몇 케이스의 입력값에 대해서만 기대하는 결과를 제공하는 오라클</h4>
<h4 id="추정heuristic-오라클-특정-테스트-케이스의-입력-값에-대해-결과를-제공하고-그-외-나머지-값은-추정으로-처리하는-오라클">추정(Heuristic) 오라클: 특정 테스트 케이스의 입력 값에 대해 결과를 제공하고, 그 외 나머지 값은 추정으로 처리하는 오라클.</h4>
